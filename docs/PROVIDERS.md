# Live research and editorial verification

The server's `src/research.mjs` uses the OpenAI Responses API with its `web_search` tool. Set `RESEARCH_API_KEY` **only in the hosting service's server secrets**. `OPENAI_API_KEY` is accepted as a fallback on hosts that permit that name; `RESEARCH_API_KEY` takes precedence and works with the cloud environment's reserved-name restrictions. Never put either credential in `public/`, browser storage, a manifest, or a client environment variable. `OPENAI_MODEL` defaults to `gpt-4.1`; choose a model that supports Responses, web search and structured output if changing it. Live searches and two model calls per accepted edition incur API costs. No paid research request is made merely by installing dependencies.

The scheduled job calls `researchEdition` before delivery; publication and delivery are separate operations. The module receives published events, used quotes and unused reserve events, so unused reserve stories also count when selecting candidates. Keep the database and research evidence on a persistent private volume and back it up. Deleting the ledger makes long-term non-repetition impossible.

For each candidate, the service performs a live search, requests two publisher sources for pivotal story details and an authoritative original text for the philosophy quote, opens every cited source, verifies its claimed excerpt against the actual document, verifies the exact quote wording, and submits the fetched passages and full event history to an independent model audit. Evidence includes exact excerpts, surrounding text, resolved URL, document SHA-256 and actual retrieval timestamp. Whitespace and typographical apostrophes/dashes are normalized for evidence matching; wording and case remain significant. Quote attribution, section and translator are also audited. A failed fetch, inaccessible page, unsupported claim, uncertain quote or semantic repeat rejects the candidate; the caller can use a previously verified unused reserve edition. Research failure must never create an unsourced substitute or republish a previous incident.

Each accepted reading contains 430-550 words, including its quote and invitation. Known duplicate events/quotes trigger at most two fresh selection attempts; the rejected candidate is added to the next attempt's exclusion history. Source, access and provider failures are not blindly retried. If all three selections repeat history, the job must consume an unused reserve or report that it cannot publish a verified new edition.

Source fetching uses a closed list of reputable public publisher and original-text archive domains, HTTPS only, no credentials or alternate ports, checked redirects, timeouts and a 3 MB response cap. Keep the inherited environment HTTP proxy and CA trust; TLS verification must stay enabled. If running Node behind an HTTP proxy, use Node's supported `NODE_USE_ENV_PROXY=1` configuration. Research needs HTTPS egress to `api.openai.com` and the cited source domains. In restricted cloud environments, allow the necessary domains in the environment settings. A policy denial cannot be fixed by changing application code.

The exact built-in publisher allowlist appears as `DEFAULT_HOSTS` at the top of `src/research.mjs`. Relevant original-text hosts include `gutenberg.org`, `classics.mit.edu`, `en.wikisource.org`, `earlymoderntexts.com` and `archive.org`. Story sources include `pbs.org`, `reuters.com`, `apnews.com`, `businessdailyafrica.com`, `nation.africa`, `techcabal.com`, company archives and the other listed publishers. Allow the actual `www.` or redirected host too when a hosting network uses exact-host egress policies. Saving an environment draft does not apply those domains to an already running machine. Verify a representative fetch after applying network settings. If only repository/package-registry access is enabled, bundled reserve reading and local tests can work while live research remains blocked.

`RESEARCH_ALLOWED_HOSTS` can add comma-separated, explicitly trusted publisher domains. Only add domains under the control of reliable public sources; this setting extends the server-side outbound-fetch trust boundary. Arbitrary URLs from users are never accepted. A configured model can still make editorial mistakes; the pipeline rejects unverifiable details and preserves evidence so future editions can be reviewed against actual sources.

No live OpenAI calls have been verified in this development environment because no research API credential was supplied. The bundled reserve is independently researched and its provenance is documented in `docs/RESEARCH.md`. Local tests can exercise validation and failure handling without credentials; they do not prove a hosting account has web-search access, sufficient balance or network permission. After adding the real server key, run the documented research command and inspect the resulting evidence before relying on unattended replenishment. Never print the key to check it.
